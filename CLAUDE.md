## Commands

```bash
npm start            # Metro bundler / Expo dev server (Expo Go)
npm run android      # open on Android device or emulator (Expo Go)
npm run ios          # open on iOS simulator (macOS only)
npm run web          # open in browser
npm run check        # typecheck: tsc --noEmit (the only check in the repo)
```

There is no test runner and no linter configured. `npm run check` is the only automated verification available — run it after changes.

The scripts pass `--go`, so the app runs in Expo Go: only use libraries that ship in Expo Go (no custom native code without moving to a dev build).

## Architecture

Expo SDK 57 app (React 19.2 / React Native 0.86 / TypeScript 6, `strict: true`) with **Expo Router** (file-based routing), NativeWind 4 and React Hook Form + Yup. It is the reference implementation of the course labs; commits are prefixed by lesson (`aulaNN: ...`).

Entry: `main` in `package.json` is `expo-router/entry`; there is no `App.tsx`/`index.ts`. Routes live in `app/`:
- `app/_layout.tsx` — root `Stack`; imports `global.css` and confirms the color scheme once on mount (needed for `dark:` classes on web).
- `app/(tabs)/` — `Tabs` with `index` (Catálogo) and `favoritos`.
- `app/(auth)/` — `login` and `cadastro`, a `Stack` without header.
- `app/produto/[id].tsx` — product detail; `app/+not-found.tsx`.

A new screen file must also be registered in the parent `_layout.tsx` when it needs options (title, `headerShown`, etc.).

`typedRoutes` is on (`app.json` `experiments`): route types are generated into `.expo/types/router.d.ts` by the dev server, so after adding or renaming a route run `npm start` once before `npm run check`, or `href`s to the new route fail the typecheck.

`src/` holds everything that is not a route:
- `src/components/` — reusable UI (`CardProduto`, `CampoTexto`, `EstadosDeLista`, `FiltroCategorias`, `BotaoTema`)
- `src/constants/` — `tema.ts` (colors, `CORES_NAVEGACAO`, `API_BASE_URL` = DummyJSON) and test products
- `src/types/`, `src/utils/`, `src/validacao/` (Yup schemas for login and cadastro)
- `src/services/`, `src/store/` — still empty, reserved for API access and global state

Import through the `@/*` → `src/*` alias (`import { X } from '@/components/CardProduto'`). The alias lives in `tsconfig.json` `paths` with **no `baseUrl`** — `baseUrl` is deprecated in TypeScript 6 and reintroducing it fails the typecheck; keep `paths` entries relative (`"./src/*"`).

### Styling and theme

Style with NativeWind `className`; custom palette tokens (`fundo`, `superficie`, `destaque`, `alerta`, `suave`, `rounded-card`) are in `tailwind.config.js`. Theme is light/dark with `darkMode: "class"`, driven by `useColorScheme` from `nativewind` (toggled by `BotaoTema`). Every screen needs both a light class and a `dark:` variant.

Navigator options (`Stack`/`Tabs` `screenOptions`, header, tab bar, `contentStyle`/`sceneStyle`) take style objects, not `className` — use `CORES_NAVEGACAO[light|dark]` from `@/constants/tema` there, and keep it in sync with the Tailwind tokens.

`/ios` and `/android` are gitignored: native projects are generated by prebuild, so never hand-edit them and prefer config plugins / `app.json` for native configuration.
